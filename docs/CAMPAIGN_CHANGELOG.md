# Campaign agent change log

## campaign-v1 / 2026-10-06

- Location: dedicated sandbox, `AGENTSHIELD_DB.ORCH`.
- Eight reusable category-specific Cortex Agents, one orchestrator, one
  summarizer and one remediation selector. Specifications are reproducibly
  generated by `scripts/build_campaigns.py` into ignored build artifacts.
- The orchestrator exposes only a bounded campaign API. Category agents,
  summarizer and remediation selector have no database mutation tools.
- Generated cases retain template ID, reference hash, exact turns, expected
  behavior, severity, generator version and prompt hash. Expected behavior is
  inherited from the seed, not written by the generator.
- The campaign evaluator is built from the same Python handler source as the
  legacy runner; no parallel copy of the evaluator is maintained.
- On-demand two-slot task execution, separate submit/start operations, serialized
  admission, one active campaign, and a finalizer for incomplete work.
- The initial live safe campaign used two category agents, four generated
  security cases and one baseline; all five recorded PASS.
- Summary/report consumers receive value-free metadata. Raw evidence remains in
  existing sandbox tables. Model-generated narrative never becomes SQL or HTML.
- No target agents modified. Apply is disabled pending verified client approval
  and an independently authorized execution identity. Reports are draft-only.

## intake-library-v1 / 2026-10-07

- Removed reference counts from chat options; added stable category labels/numbers,
  target aliases, Quick/Standard/Thorough presets and non-starting sample questions.
- Updated only the sandbox orchestrator instructions; preserved its other live
  specification fields, object identity and grants. Private version snapshots
  are retained in ignored build artifacts.
- Added 65 reference templates, reaching 15 per security category. All original
  rows and six demo-only cases are unchanged. Migration reapplication verified.
- Preset/custom setup and options-only responses smoke-tested without dispatch.
  One generation-only invocation validated expanded indirect-injection references.
- CoWork native selection controls are not implemented or verified. No target
  changes, no apply operation, and no SnowBots source changes.
